# 逐字重合检查

```sh
npm run copyright:check
npm test
# 额外检查运行时答案或浏览器抽取的文本文件（仓库外）
npm run copyright:check -- --extra /tmp/answer.txt
# 只在原始只读 clone 完整存在时重建哈希
npm run copyright:hashes
```

基线覆盖全部 1,848 条记录（不限于提炼子集）、原 29 条语录和原 9 个合盘引用字段。原始 JSONL 没有 id，方法规则采用其一基行号，不修改源文件。

- NFKC 后仅保留汉字。这比仅去标点空白更严格：数字或拉丁文字也不能作为规避手段。
- 在每个源条目内分别建立 8 字与 10 字窗口，存 SHA-256，不跨不相邻条目拼接。原文、注释、主题字段均纳入。
- 任意 10 字连续重合即失败。8 字窗口按出现次数计算，命中窗口数 / 产出窗口数 **大于 0.1** 即失败；等于 0.1 不失败。少于 8 字没有窗口，但不能据此把受保护句子拆成小片段。
- 源码扫描覆盖 app、components、lib 的字符串、模板固定部分、JSX 文本及相邻静态格式节点，另扫方法 JSON、文档和 README。方法出处只含不可逆证据指纹，不是原句。
- 不以文件名或目录名豁免“古籍”。当前库混有现代整理，全部纳入；真正公版引文若触发，应单独核校权利与版本，而不是扩大白名单。
- 原始 checkout 缺失时明确提示跳过原文核验，但使用提交的全量哈希继续检查，不跳过 CI 文案扫描。基线 108,362 个 8 字哈希、104,985 个 10 字哈希。固定哈希有低熵片段被枚举猜测的理论风险，不提供原文恢复接口。
- `npm test` 的回归用独立的合成字串验证阈值，再从外部原文动态取样验证阳性。测试文件不复制真实原句。

运行时 AI 不是固定文案：本任务对实测答案另行检查，但本脚本不是流式输出拦截器，不能保证第三方模型未来每次输出都合规。不能用高分或“通过”替代人工权利审查、近似表达审查或专业法律意见。
